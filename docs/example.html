The run story

A feedback trace, not just a collection of outputs

The driver normally writes to 5t_ota/. This snapshot is stored as 5t_ota_example_run/ so publishing it does not confuse it with a live workspace. The driver deletes an existing WORK_DIR before every run.

01

Understand

The full DUT is simplified for LLM context, and a gm/Id agent creates the topology-aware specification.

02

Propose

The current prompt produces structured equations, which are recorded in history and compiled into Python.

03

Size

The scalar evaluator and gm/Id LUT produce a device solution and the stage's .1 report.

04

Measure

Updated device parameters drive universal HSPICE decks; raw results become a stage SPICE report.

05

Verify

Extracted operating points feed the same model, creating the .2 report used for comparison.

06

Correct

Mismatch becomes the next prompt. At stage 9 the equations pass closure and the model is vectorized.

Disposable cache

Python bytecode only. It affects import speed, not equations, sizing, simulation, or convergence.

How to inspect stage N

Read one horizontal slice across the run

Use the same stage number across directories. This reconstructs exactly what the framework proposed, predicted, simulated, and fed back.

  1. Prompt: open prompts/prompt_stageN.txt to see the information given to the model.
  2. Proposal: inspect llm_outputs/llm_output_stageN.json for topology mapping and equations.
  3. Executable model: read ota_models/ota_model_stageN.py, compiled from that JSON.
  4. LUT sizing: inspect ota_model_performance/ota_model_estimation_stageN.1.json and the parameters it selected.
  5. Simulator truth: compare spice_performance/spice_estimation_stageN.json with the same row in design_sweep_log.csv.
  6. Equation verification: compare the SPICE report with ota_model_estimation_stageN.2.json; mismatch appears in the next prompt.

Reproduce and extend

Use the snapshot as a reference, not as the live workspace

# The configured driver creates and owns 5t_ota/
bash llm_aided_modelling.sh

# Compare the fresh workspace with the preserved example
diff -ru 5t_ota_example_run 5t_ota

A byte-for-byte match is not expected: LLM responses, timestamps, simulator products, and optimization results can vary. Compare schemas, stage lineage, convergence behavior, and performance trends. A real run also requires API configuration, HSPICE on PATH, and accessible foundry models.
