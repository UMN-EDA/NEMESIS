5T OTA model refinement

This example documents nine iterations of analytical model refinement for a five-transistor OTA. Model predictions are compared with HSPICE measurements at each iteration, and the converged scalar model is converted to a vectorized evaluator.

Modeling procedure

Iterative equation refinement using HSPICE measurements

The driver normally writes to 5t_ota/. This snapshot is stored as 5t_ota_example_run/ so publishing it does not confuse it with a live workspace. The driver deletes an existing WORK_DIR before every run.

01

Extract circuit topology

The DUT netlist is reduced to the device and node information required to formulate topology-dependent equations and gm/Id constraints.

02

Generate analytical equations

Each iteration produces a structured set of performance equations. The equations are recorded and compiled into an executable Python model.

03

Perform LUT-based sizing

The scalar model and gm/Id lookup table generate device dimensions and the iteration's .1 prediction report.

04

Run HSPICE characterization

The selected device parameters are applied to the testbenches. Extracted measurements are stored in the corresponding HSPICE report.

05

Evaluate with operating points

HSPICE operating-point parameters are supplied to the analytical equations to generate the .2 prediction report.

06

Calculate relative error

Model predictions are compared with HSPICE measurements. Equations exceeding the tolerance are revised in the next iteration; iteration 9 meets the convergence criterion.

Iteration data

Inspect the files for a single iteration

Use the same iteration number across directories to identify the equations, model predictions, HSPICE measurements, and error-correction input.

  1. Prompt: open prompts/prompt_stageN.txt to see the information given to the model.
  2. Proposal: inspect llm_outputs/llm_output_stageN.json for topology mapping and equations.
  3. Executable model: read ota_models/ota_model_stageN.py, compiled from that JSON.
  4. LUT sizing: inspect ota_model_performance/ota_model_estimation_stageN.1.json and the parameters it selected.
  5. HSPICE measurements: compare spice_performance/spice_estimation_stageN.json with the same row in design_sweep_log.csv.
  6. Equation verification: compare the SPICE report with ota_model_estimation_stageN.2.json; mismatch appears in the next prompt.

Reproduce and extend

Use the snapshot as a reference, not as the live workspace

# The configured driver creates and owns 5t_ota/
bash llm_aided_modelling.sh

# Compare the fresh workspace with the preserved example
diff -ru 5t_ota_example_run 5t_ota

A byte-for-byte match is not expected: LLM responses, timestamps, simulator products, and optimization results can vary. Compare schemas, stage lineage, convergence behavior, and performance trends. A real run also requires API configuration, HSPICE on PATH, and accessible foundry models.
